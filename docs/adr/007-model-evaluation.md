# ADR 007 — Model Evaluation & Cost Matrix

## Status
Planned — implementation Day 5

## Context
Multiple transformer models could serve each task. We need a principled
way to choose between them based on accuracy, latency, memory, and cost.
This evaluation framework makes the choice defensible in the interview
and in production.

## Evaluation framework

### Structure
```
evaluations/
├── datasets/
│   ├── sentiment_eval.csv     ← labelled product reviews (pos/neg)
│   ├── intent_eval.csv        ← labelled customer queries (27 intents)
│   └── triage_eval.csv        ← labelled complaints (low/med/high)
├── scripts/
│   ├── run_sentiment_eval.py
│   ├── run_intent_eval.py
│   └── run_triage_eval.py
├── results/
│   └── results.json           ← auto-generated by eval scripts
└── cost_matrix.md             ← human-readable summary
```

### Metrics per task
- Accuracy / F1 score (weighted)
- p50 latency (ms) — median request
- p99 latency (ms) — worst case
- Memory footprint (MB) — model in memory
- Estimated cost per 1M requests (CPU instance)

## Cost estimation methodology
```
CPU instance: AWS c5.xlarge = $0.17/hr
Requests per hour at p50 latency:
  distilbert @ 50ms = 72,000 req/hr
  bert-base  @ 150ms = 24,000 req/hr

Cost per 1M requests:
  distilbert = $0.17 / 72,000 * 1,000,000 = $2.36
  bert-base  = $0.17 / 24,000 * 1,000,000 = $7.08
```

## Interview line
> "I ran evaluations across three model sizes per task. DistilBERT
> gives 92% of BERT-base accuracy at 3x the throughput and 1/3 the
> cost. For dunnhumby's scale that's the right trade-off — the 8%
> accuracy gap doesn't justify 3x infrastructure cost."
